# Runasis 러닝 질문별 최소 조작 경로

작성일: 2026-06-15

이 문서는 사용자가 자주 묻는 러닝 질문을 Runasis 안에서 어떻게 답하거나 수행할 수 있는지 정리한다. 기준은 현재 앱 구조다: `Dashboard`, `Activities`, `Personal Bests`, `Analysis`.

## 공통 전제

먼저 상단 상태가 다음 수준까지 준비되어 있어야 한다.

- `Connected`: Strava 연결 완료.
- `Import Activities` 또는 `Update from Strava`: 활동 목록과 상세 기록 동기화.
- `Best efforts ... · Streams ...`: Personal Bests, Riegel, Top N 목표, GPS 오류 제외는 상세/스트림 데이터가 많을수록 정확하다.

기록이 이상하거나 비어 보이면 `Activities`에서 해당 활동을 검색한 뒤 새로고침 아이콘으로 상세 기록을 다시 가져온다.

## 1. 최근 30일간 몇 km 뛰었고, 이 추세면 1년에 몇 km인가?

현재 앱에서의 최소 경로:

1. `Dashboard`를 연다.
2. `Range`를 `Last 30 days`로 둔다. 기본값이 이미 `Last 30 days`다.
3. `Distance` 카드의 km 값을 읽는다.
4. `Distance` 카드의 `Annualized ... km/yr` 값을 읽는다. `Last 30 days`라면 `최근 30일 km x 365 / 30`으로 계산된 값이다.

현재 도달성: 최근 30일 km와 연간 환산값은 Dashboard에서 바로 확인 가능하다. `Range`를 다른 숫자 기간으로 바꾸면 그 기간 기준 연환산으로 바뀐다.

최소 조작 보강점: 이미 반영됨. 남은 개선 여지는 연환산 기준 기간을 카드 안에 더 명시하는 정도다.

## 2. 내 달리기 기록은 시간에 따라 좋아지고 있는 추세인가?

현재 앱에서의 최소 경로:

1. `Personal Bests`를 연다.
2. 분석할 기준을 고른다: `Distance`, `Time`, 또는 `Pace`.
3. 하위 탭에서 `Trend`를 연다.
4. `Top 5`, `Top 10`, `Top 20` 중 비교 범위를 고르고, 거리/시간/페이스 선택 박스를 고른다.
5. 추세선의 방향을 본다. 거리/시간 기준에서는 페이스가 낮아지는 방향이 개선이고, 페이스 기준에서는 같은 페이스를 더 오래/멀리 유지하는 방향이 개선이다.

현재 도달성: 추세 차트는 있다. 다만 앱이 "개선 중/정체/악화"를 한 문장으로 판정하지는 않는다.

최소 조작 보강점: `Runner Brief`나 `Performance Focus`에 `Recent record trend: improving / flat / slower` 같은 요약 판정을 추가하면 탭 이동 없이 답할 수 있다.

## 3. 다음 마라톤 대회에서 4시간 이내 기록이 가능할까?

현재 앱에서의 최소 경로:

1. `Analysis`를 연다.
2. 상단 `Race Target`에서 `Distance`를 `Marathon`으로 둔다. 기본값이 `Marathon`이다.
3. `Goal time`을 `4:00:00`으로 둔다. 기본값도 `4:00:00`이다.
4. 결과 문구를 읽는다.
   - `On track by ...`: 현재 Riegel projection상 목표보다 빠르다.
   - `Need ... faster`: 현재 projection상 목표보다 느리며, 필요한 초/km 개선량도 같이 표시된다.
   - `Collect more best efforts`: 비교 가능한 개인 기록이 부족하다.

현재 도달성: 1클릭(`Analysis`)이면 답이 나온다. 단, Riegel 기반 예측이므로 훈련 상태, 코스, 날씨, 보급, 부상 위험은 반영하지 않는다.

최소 조작 보강점: Dashboard의 `Runner Brief`에 마라톤 목표 상태를 한 줄로 노출하면 앱 첫 화면에서 바로 확인할 수 있다.

## 4. 오늘 러닝에서 내 Top N 기록 이내를 기록하려면 어떻게 달려야 할까?

현재 앱에서의 최소 경로:

1. `Personal Bests`를 연다.
2. 목표 방식에 맞춰 `Distance`, `Time`, `Pace` 중 하나를 고른다.
3. `Target rank`에서 원하는 N을 고른다. 기본값은 `Top 10`이고, 화면에서는 `Top 3`, `Top 5`, `Top 10`, `Top 20`을 바로 고를 수 있다.
4. `Records`에서 목표 항목을 선택한다.
5. 선택한 항목 위의 `Top N target today` 값을 기준으로 오늘 목표를 잡는다.
   - 거리 기록: 표시된 시간보다 빠르게 완주한다.
   - 시간 기록: 표시된 거리보다 더 멀리 달린다.
   - 페이스 기록: 표시된 지속 시간보다 오래 유지한다.

현재 도달성: 앱 안에서 바로 가능하다. 목표 N에 해당하는 기록이 아직 없으면 목표 카드는 표시되지 않으므로 기록 수를 먼저 확인한다.

최소 조작 보강점: 이미 반영됨. 남은 개선 여지는 사용자가 직접 N을 입력하는 고급 옵션이다.

## 5. 내 기록에서 유추되는 나의 Riegel 지수는 몇인가?

현재 앱에서의 최소 경로:

1. `Analysis`를 연다.
2. `Model settings`를 펼친다.
3. `Median` 모드를 선택한다. 현재 기본값도 `Median`이다.
4. `Exponent` 값을 읽는다.

해석:

- 기본 Riegel 지수는 `1.060`이다.
- 앱의 `Median` 모드는 유효한 거리 개인기록 쌍 전체에서 지수를 계산하고 중앙값을 쓴다.
- 지수가 높을수록 긴 거리에서 상대적으로 더 많이 느려진다는 뜻이고, 낮을수록 거리가 길어져도 페이스 유지가 좋다는 뜻이다.

현재 도달성: `Analysis`에서 바로 가능하다. 비교 가능한 거리 기록 쌍이 부족하면 기본값 `1.060`에 가까운 결과가 쓰인다.

최소 조작 보강점: `Performance Focus` 카드에 현재 지수를 상시 노출하면 `Model settings`를 펼치지 않아도 된다.

## 6. 내 Riegel 지수 기준으로 기록 갱신이 예상되는 거리/시간/페이스는 무엇인가?

현재 앱에서의 최소 경로:

1. `Analysis`를 연다.
2. 상단 `Performance Focus`의 `Limiter`와 `Next Focus`를 먼저 본다.
3. `Pace by Distance`에서 기대 기록 대비 현재 기록을 본다.
4. 필요하면 `More model detail`을 펼쳐 `Pace by Distance Comparison` 표를 확인한다.
5. `Pace by Time`, `Distance by Pace` 탭도 같은 방식으로 본다.

판단 방법:

- 현재 기록이 기대치보다 약한 항목은 갱신 여지가 큰 후보로 본다.
- 현재 기록이 기대치보다 강한 항목은 이미 상대적으로 잘 나온 거리/시간/페이스다.
- `Limiter`와 `Next Focus`는 앱이 이 차이를 요약해 주는 가장 가까운 답이다.

현재 도달성: `Expected PRs` 카드에서 갱신 후보를 바로 볼 수 있다. 더 자세한 근거가 필요하면 `More model detail`의 비교 표와 차트를 확인한다.

최소 조작 보강점: 이미 반영됨. 남은 개선 여지는 후보별 추천 workout까지 연결하는 것이다.

## 7. 오늘 아침 내 러닝은 기존 러닝 기록과 비교할 때 어느 정도인가?

현재 앱에서의 최소 경로:

1. 오늘 아침 러닝을 Strava에서 동기화한다.
2. `Dashboard`의 `Latest Run` 카드를 읽는다.

앱이 보여주는 비교:

- 최신 러닝 날짜, 거리, 페이스, 시간.
- 최신 러닝이 표준 거리 개인기록과 맞으면 해당 기록 대비 차이.
- 매칭되는 개인기록이 부족하면 저장된 러닝 중 거리 순위.

현재 도달성: 동기화 후 Dashboard 첫 화면에서 바로 확인 가능하다.

최소 조작 보강점: `Latest Run` 카드에 선택한 `Target rank` 기준의 Top N 여부와 가장 가까운 기록 대비 차이가 표시된다. 남은 개선 여지는 비교 기준 거리를 사용자가 직접 고르는 옵션이다.

## 8. GPS 에러로 잘못 측정된 기록은 어떻게 제외할 수 있는가?

현재 앱에서의 최소 경로:

1. `Personal Bests`를 연다.
2. 잘못 반영된 기록이 있는 `Distance`, `Time`, `Pace` 탭을 연다.
3. `Records`에서 해당 기록 행의 제외 아이콘을 누른다.
4. 제외된 기록은 기본 Personal Bests, Analysis, Race Target 계산에서 빠진다.
5. 다시 확인하거나 복구하려면 `Include Excluded`를 누른 뒤 빨간색 제외 기록 행의 포함 아이콘을 누른다.

대안:

- Strava에서 원본 활동을 수정할 수 있으면 먼저 Strava에서 수정한 뒤, Runasis의 `Activities`에서 해당 활동을 검색하고 새로고침 아이콘을 누른다.
- 원본을 수정할 수 없거나 best-effort 일부만 잘못되었으면 Runasis에서 해당 record만 제외한다.

현재 도달성: 앱 안에서 수행 가능하다. 제외 목록은 로컬 파생 데이터로 저장되고, 원본 Strava 데이터는 삭제하지 않는다.

최소 조작 보강점: `Activities`의 활동 카드에서 "이 활동에서 생긴 PB 제외"로 바로 연결하면 검색과 탭 이동을 줄일 수 있다.

## 9. 최근 기록들을 고려할 때 오늘 달리기는 어떤 페이스로 어떻게 하면 좋은가?

현재 앱에서의 최소 경로:

1. `Dashboard`의 `Today` 카드를 읽는다.
2. 더 자세히 보려면 `Analysis`를 열고 `Next run options`를 펼친다.
3. `Performance Focus`의 `Limiter`와 `Next Focus`를 함께 본다.

현재 앱의 판단 기준:

- 오늘 이미 달렸으면 회복 또는 휴식을 제안한다.
- 연속 러닝일이 많거나 최근 7일 거리가 30일 기준 주간 베이스라인보다 높으면 강도를 낮추라고 제안한다.
- 최근 기록과 분석 신호가 충분하면 통제된 workout 옵션을 제안한다.
- 근거가 부족하면 workout 추천을 하지 않는다.

현재 도달성: 안전한 방향의 제안과 개인 기록 기반 페이스 밴드는 Dashboard에서 바로 나온다. 기록 근거가 부족하면 workout 추천 대신 보수적인 안내가 표시된다.

최소 조작 보강점: 이미 반영됨. 남은 개선 여지는 오늘의 컨디션, 날씨, 코스 난이도를 반영하는 입력이다.

## 반영된 앱 보강

1. Dashboard `Distance` 카드에 선택 기간 기준 연간 환산 km를 표시한다.
2. Dashboard `Latest Run`에 선택한 `Target rank` 기준 Top N 여부와 가장 가까운 기록 대비 차이를 표시한다.
3. Personal Bests의 목표 항목에 `Top N target today` 값을 표시한다.
4. Analysis에 `Expected PRs` 카드로 기록 갱신 후보를 정렬한다.
5. Dashboard `Today` 카드에 개인 기록 기반 페이스 밴드를 추가한다.

이 다섯 가지가 들어가면서 위 질문 대부분은 Dashboard 또는 한 번의 탭 이동 안에서 답할 수 있다.
